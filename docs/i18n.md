# Internationalization (I18n) Guide

PermissionForge is fully internationalized. All admin UI strings, flash messages, and API error messages use Rails I18n.

## Supported Languages

| Locale | Language | File |
|--------|----------|------|
| `en` | English | `config/locales/permission_forge.en.yml` |
| `sq` | Shqip | `config/locales/permission_forge.sq.yml` |
| `mk` | Makedonski | `config/locales/permission_forge.mk.yml` |

## How It Works

### Admin UI

The admin UI includes a locale switcher in the sidebar. Clicking a language sets the locale in the session, so it persists across page loads. You can also pass `?locale=sq` as a query parameter.

Switcher links carry only the current path plus the validated `locale` param — other query parameters are not preserved (this prevents reflected-parameter tricks from turning the switcher into an off-site link).

The locale is resolved in this order:
1. `params[:locale]` (if valid)
2. `session[:permission_forge_locale]` (persisted from previous switch)
3. `I18n.default_locale` (fallback)

### JSON API

The API accepts locale via:
1. `locale` query/body parameter (highest priority)
2. `Accept-Language` HTTP header
3. `I18n.default_locale` (fallback)

```bash
# Via query parameter
curl /permission_forge/api/permission_sets?locale=sq

# Via Accept-Language header
curl -H "Accept-Language: sq" /permission_forge/api/permission_sets
```

`Accept-Language` parsing accepts bare tags (`en`), region forms (`en-US`), and lists with q-weights (`en-US;q=0.8,sq`) — each tag is reduced to its primary language subtag. **q-values are ignored**: the first tag, in the order the header lists them, whose primary subtag is an available locale wins (`en;q=0.1, sq` gives `en`). A `locale` parameter that is not an available locale is not combined with the header: the request falls back to `I18n.default_locale`. The locale is reset on every request (falling back to `I18n.default_locale` when none matches), so one request's locale never leaks into the next.

### Configuration

```ruby
PermissionForge.configure do |config|
  # Limit which locales are loaded.
  # nil (default) falls back to PermissionForge::BUNDLED_LOCALES ([:en, :sq, :mk])
  config.available_locales = [:en, :sq, :mk]
end
```

Only matching locale files are loaded. When `available_locales` is unset, the gem falls back to `PermissionForge::BUNDLED_LOCALES` — the locales it ships translations for (`[:en, :sq, :mk]`) — so the admin UI never offers host-app locales (e.g., ones added by Faker) that the gem can't translate.

## Overriding Translations

Host app locale files load after engine locale files, so you can override any key by defining it in your own locale file:

```yaml
# config/locales/permission_forge_overrides.en.yml
en:
  permission_forge:
    nav:
      permission_sets: "Roles"
    flash:
      permission_sets:
        created: "New permission set saved!"
```

## Model Attribute Translations

Form labels for model attributes use Rails' built-in `activerecord.attributes.*` convention. If your host app translates attributes, PermissionForge picks them up automatically:

```yaml
# config/locales/en.yml (in your host app)
en:
  activerecord:
    attributes:
      permission_forge/permission_set:
        name: "Set Name"
        description: "Set Description"
```

## Adding a New Language

### Step 1: Create the Locale File

Copy the English reference file:

```bash
cp config/locales/permission_forge.en.yml config/locales/permission_forge.XX.yml
```

### Step 2: Update the Top-Level Key

Change `en:` to your locale code (e.g., `pt:` for Portuguese).

### Step 3: Translate All Values

Translate every string value. Keep these unchanged:
- Interpolation variables: `%{count}`, `%{name}`, `%{time}`, `%{id}`, `%{error}`, `%{resource}`
- HTML markup in `_html` suffix keys (e.g., `<code class="pf-mono">current_user</code>`)
- Brand name: "PermissionForge"
- Technical abbreviations: "UUID", "CRUD", "R", "C", "E", "D"
- Code tokens: `current_user`, `example.com`, `company.organization`

### Step 4: Verify with i18n-tasks

```bash
bundle exec i18n-tasks missing
bundle exec i18n-tasks unused
```

### Step 5: Register the Locale

Update `ApplicationHelper::LOCALE_LABELS` in `app/helpers/permission_forge/application_helper.rb`:

```ruby
LOCALE_LABELS = {
  en: 'English',
  sq: 'Shqip',
  mk: 'Makedonski',
  # ... add your locale:
  pt: 'Portugues',
}.freeze
```

Also add the locale to `PermissionForge::BUNDLED_LOCALES` in `lib/permission_forge.rb`. The engine only loads locale files whose locale appears in `config.available_locales` (or, when unset, `BUNDLED_LOCALES`) — an unregistered file is never loaded.

### Step 6: Submit a PR

Community translations are welcome! Please ensure:
- All keys match the English reference file (no missing or extra keys)
- Interpolation variables are preserved
- Pluralization forms (`one`/`other`) are grammatically correct
- `_html` suffix keys preserve HTML markup

## Key Reference

All keys live under the `permission_forge:` namespace:

| Namespace | Purpose | Example Key |
|-----------|---------|-------------|
| `ui` | Shared admin vocabulary: levels, states, operators, badges, dates, change descriptions | `permission_forge.ui.levels.masked` |
| `nav` | Sidebar navigation | `permission_forge.nav.permission_sets` |
| `shared` | Shared partials (frames, cells, savebar, expiry picker, audit footer) | `permission_forge.shared.savebar.review` |
| `home`, `people`, `assignments`, `bulk_assignments` | Home and people screens | `permission_forge.people.show.tabs.effective` |
| `permission_sets`, `resources`, `resource_fields`, `resource_actions`, `permission_set_rules` | Permission Set editor, resource page, field drawer, actions, rule builder | `permission_forge.permission_set_rules.builder.preview` |
| `permission_set_groups`, `field_lookups` | Groups and Field lookup | `permission_forge.field_lookups.show.who_can_see` |
| `settings` | Read-only Settings page; `settings.items.<key>.name/desc` for every option | `permission_forge.settings.items.cache_ttl.name` |
| `flash` | Toast messages | `permission_forge.flash.assignments.assigned` |
| `errors.admin` | Admin form validation messages | `permission_forge.errors.admin.ip` |
| `api.errors` | API error messages | `permission_forge.api.errors.not_found` |
| `layouts` | Page title | `permission_forge.layouts.application.title` |
| `validations` | Model validation messages | `permission_forge.validations.resource.invalid_name` |

Dates in the admin use the engine's own month names (`ui.months.*`), so the host app does not need `rails-i18n`.

## Translation Quality Disclaimer

Built-in translations (sq, mk) are provided as a convenience. **We do not guarantee the accuracy of non-English translations.** If you find an error, please submit a PR with the correction.

## Development: i18n-tasks

The gem ships with an `i18n-tasks` configuration at `config/i18n-tasks.yml`. Use it to verify translation health:

```bash
# Full health check
bundle exec i18n-tasks health

# Find missing translations
bundle exec i18n-tasks missing

# Find unused translations
bundle exec i18n-tasks unused

# Normalize locale files (consistent key ordering)
bundle exec i18n-tasks normalize
```

Add `bundle exec i18n-tasks health` to your CI pipeline to catch missing translations early.
